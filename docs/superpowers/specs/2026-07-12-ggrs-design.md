# ggrs — порт llama.cpp/ggml на Rust с обучением на CPU

**Дата:** 2026-07-12
**Статус:** дизайн утверждён

## Цель

Долгосрочный проект: полноценный Rust-порт llama.cpp/ggml (подход «точный порт ggml» —
статический граф вычислений, GGUF, потоковая модель ggml), в котором обучение —
первоклассная возможность, а не надстройка. Первая большая веха: обучить с нуля
собственный трансформер ~10M параметров на TinyStories на CPU (Ryzen 7 7730U).

## Контекст и ограничения

- Железо: Ryzen 7 7730U (8 ядер / 16 потоков, AVX2+FMA, **без** AVX-512/AMX),
  ~16+ ГБ RAM, Windows 11. Всё из исходных исследовательских доков про AMX, NUMA,
  мультисокетность — вне скоупа.
- Исходные доки (Perplexity/AI-generated) — источник идей, не спецификация:
  «эмпирика» в них выдумана, часть API не существует. Реальны и полезны: математика
  DPO-лосса, QAT-градиенты через scale/offset, Newton-Schulz (Muon), ReLoRA/EWC,
  блочно-диагональные маски внимания. Это бэклог Фазы 7.
- Эталон корректности: настоящий llama.cpp (локальная сборка llama-turboquant,
  `C:\Users\pavel\llama-turboquant`).

## Ядро (ggrs-core)

**Адаптация арены к Rust** (единственное осознанное отступление от буквального
порта): `Context` владеет bump-аллокатором и таблицей тензоров; снаружи тензор —
`TensorId` (индекс), не указатель. Семантика ggml сохраняется (арена, нулевые
копии, views со смещениями), unsafe остаётся внутри compute-ядер.

**Типы** (ретрофит Фазы 1.5 по итогам исследования): ggml-стиль type traits —
`blck_size`/`type_size`/`row_size`; страйды и contiguity через traits, что делает
блочно-квантованные форматы (Q8_0/Q4_K, Фазы 5/7) выразимыми без переделки ядер.
DType: F32, F16 (собственные IEEE binary16 конверсии, zero deps), I32.
Телеметрия: `GGRS_PROFILE=1` — per-op тайминги (фундамент спидрана), `util::Lcg` —
детерминированные сиды.

**Tensor** (порт `ggml_tensor`): dtype (F32, F16, I32, позже квантованные),
`ne: [i64; 4]`, `nb: [usize; 4]` (страйды в байтах), `op: Op`,
`src: [Option<TensorId>; 4]` (RoPE и cross-entropy требуют >2 источников;
расширим, если понадобится), смещение в арене, флаг `param`.

**Ops** — только нужное для GPT, расширяем по надобности:
`Add, Mul, MulMat, Scale, RmsNorm, Silu, Gelu, SoftMax, Rope, GetRows,
Reshape/Permute/Cont, CrossEntropyLoss` (View и Cpy из ggml не нужны в Фазе 1:
Reshape+Permute+Cont покрывают потребности GPT-графа).
Каждая операция: `forward`-ядро + `backward` (строит градиентные узлы графа).

**Граф** (порт `ggml_cgraph`): построение обходом от результата
(`build_forward_expand`), `Vec<TensorId>` в топологическом порядке.
Выполнение — модель потоков ggml: N потоков, деление узла по строкам,
барьеры между узлами.

**SIMD с первого дня**: каждое горячее ядро в двух вариантах — скалярный эталон
и AVX2+FMA через `std::arch` (аналог `ggml_vec_dot_f32`). Тесты сравнивают оба
пути по допуску.

**Память**: простая арена «всё живёт до конца шага». Планировщик с
переиспользованием буферов (аналог `ggml_gallocr`) — фаза оптимизации.

## Обучение (ggrs-opt)

- **Backward** — порт `ggml_build_backward_expand`: параметры помечаются,
  backward каждой операции достраивает узлы градиентов в тот же граф.
- **Gradcheck** конечными разностями (аналог `test-grad0`) обязателен для каждой
  операции до включения в модель.
- **AdamW**, фьюзнутый AVX2-цикл. Клиппинг по глобальной норме + NaN/Inf-guard
  с первого дня.
- Muon/GaLore/DPO/QAT — бэклог Фазы 7.

## Модель и данные (ggrs-model)

- GPT-стиль: RMSNorm, RoPE, SwiGLU FFN, tied embeddings.
- Первый малыш: ~10M параметров (d=256, 8 слоёв, 8 голов, ctx 512, vocab 4096).
- Свой обучаемый BPE-токенизатор (логика словаря llama.cpp), словарь 4096.
- Данные: TinyStories (HuggingFace, берём 100–300 МБ), предтокенизация в
  бинарный файл, mmap при обучении. Смоук — char-level Шекспир.

## GGUF (ggrs-gguf)

Чтение и запись с первого дня; чекпоинты обучения — сразу GGUF (метаданные
архитектуры + тензоры f32). Интеграционный критерий: наш GGUF загружается в
настоящий llama.cpp и генерирует текст. Квантование и загрузка чужих GGUF —
Фаза 5.

## Тестирование

1. Юнит-тесты операций: скаляр vs AVX2, фиксированные сиды.
2. Gradcheck конечными разностями для каждой backward-операции.
3. Эталонные фикстуры из numpy (Python 3.12 локально; у llama-turboquant нет
   исходников ggml, только бинарники — компилировать генератор не из чего),
   совпадение по допуску. Настоящая проверка совместимости с ggml — п.4.
4. Интеграция: обученный GGUF работает в llama.cpp.
5. Смоук обучения: loss на Шекспире падает ниже порога за N шагов.

## Роадмап

- **Фаза 1**: ggrs-core — арена, тензоры, forward-операции (скаляр+AVX2),
  потоки, тесты против ggml-эталонов.
- **Фаза 2**: backward + gradcheck + AdamW → крошечный MLP сходится на
  игрушечной задаче. Включает новую операцию **OutProd** (внешнее произведение,
  порт ggml_out_prod) — без неё нет ∇W у MulMat; найдено ревью 2-го круга Ф1 (F4).
- **Фаза 3**: BPE + GPT + char-Шекспир → **TinyStories 10M** (главная веха).
- **Фаза 4**: GGUF-запись/чтение, чекпоинт грузится в llama.cpp.
- **Фаза 5**: квантование (Q8_0/Q4_0/Q4_K), inference чужих GGUF (Qwen-0.5B).
- **Фаза 6**: бенчмарки против llama.cpp, цель ≥50% его скорости.
- **Фаза 7** (исследовательская): LoRA, Muon, DPO, QAT из исходных доков.

## Критерий успеха MVP (фазы 1–4)

`ggrs-train` обучает 10M модель на TinyStories на 7730U за ≤48 часов до связных
историй; чекпоинт совместим с настоящим llama.cpp.
