# Фаза 4: GGUF — экспорт/импорт, совместимость с llama.cpp — Implementation Plan

> **For agentic workers:** исполнение по docs/process/workforce.md (dev_agent.py + cargo-раннер;
> контролёр — Sonnet 5; ревью и приёмка — архитектор). Каждая задача АТОМАРНА: свой тест-цикл,
> свой коммит, независимая проверка. Чекбоксы `- [ ]`.

**Goal:** наш обученный чекпоинт (TinyStories-10M, `ts10m_baseline/ckpt.ggrs`) конвертируется
в GGUF, который **настоящий llama.cpp загружает и генерирует связный текст** (ВЕХА, критерий
MVP из дизайн-спеки). Плюс: наш собственный reader читает наши GGUF назад с побитовым
round-trip логитов, и закрывается AUDIT-3 (зависание compute при панике worker'а).

**Architecture:** новый крейт `crates/ggrs-gguf` — чистый кодек контейнера GGUF v3
(метаданные KV + тензорные записи + выравнивание), **без зависимостей вообще, включая
ggrs-core** (оперирует именами/формами/байтами). Семантика модели (маппинг наших тензоров
и токенизатора на конвенции llama.cpp) живёт в `ggrs-model` (`gguf_map.rs`) + два бина
(`gguf_export`, `gguf_info`) + `--gguf` в `generate`. Квантованные типы и чужие GGUF —
Фаза 5; здесь только F32 и наша собственная архитектура.

## Global Constraints

- Атомарность: одна задача = один аспект = свои тесты = свой коммит (метка исполнителя);
  >3 файлов кода — возврат архитектору на распил.
- Zero deps — закон (в т.ч. ggrs-gguf; mmap не берём: `std::fs::read`).
- clippy `-D warnings`; существующие 144 теста не трогать (исключение: T2 правит
  shakespeare_smoke по явному скоупу).
- Hardening-стандарт AUDIT-2 для ВСЕХ читателей файлов: повреждённый вход → `io::Error`,
  не паника и не OOM (лимиты на счётчики/длины, checked-арифметика, точная сверка размера).
- Ветка `phase-4-gguf` от master. Один пишущий исполнитель за раз.

## Решения фазы (зафиксированы, в брифах не пересматривать)

1. **Роли форматов**: GGRS1 остаётся тренировочным чекпоинтом (веса + m/v оптимизатора + rng);
   GGUF — формат экспорта/обмена (только веса + метаданные). Спека «чекпоинты сразу GGUF»
   де-факто пересмотрена Фазой 3 — узаконено здесь. Сайдкар train-state в GGUF — бэклог Ф7.
2. **Целевая архитектура llama.cpp: `llama`**. Наш GPT — LLaMA-стиль (RMSNorm+RoPE
   NORM+SwiGLU, без bias); rope NORM у llama-арки дефолтный, наши ядра портированы из ggml
   и сверены numpy-фикстурами (Ф1) — режим совпадает по построению.
3. **RMSNorm без гаммы** → экспортируем синтетические единичные векторы
   `blk.{i}.attn_norm.weight`, `blk.{i}.ffn_norm.weight`, `output_norm.weight` (все 1.0, [d]).
   eps = **1e-5** (фактическое значение `build_gpt`, gpt.rs:150,211 — НЕ угадывать заново).
4. **Tied embeddings** → `output.weight` НЕ пишем (llama.cpp переиспользует `token_embd`);
   стоп-кран: флаг `--duplicate-output` у экспортёра пишет копию (см. Риски).
5. **Токенизатор** → `tokenizer.ggml.model = "gpt2"` (byte-level BPE): токены рендерятся
   через **каноническую GPT-2 таблицу byte↔unicode** (printable-байты как есть, остальные
   в сдвинутые кодпоинты: 0x20→'Ġ', 0x0A→'Ċ', …), merges — строки «left right» в том же
   рендере. `tokenizer.ggml.pre = "gpt-2"`. Спец-токенов у нас НЕТ: token_type все NORMAL(1),
   `bos=0, eos=0, add_bos_token=false, add_eos_token=false` — байт 0x00 в TinyStories не
   встречается, стоп-по-eos не сработает, генерация ограничивается `--n-predict` (норма для вехи).
6. **GGUF v3**, little-endian, `general.alignment = 32`, `general.file_type = 0` (ALL_F32).
   Файлы > 4 ГиБ не поддерживаем (наш d10m ≈ 30 МБ); лимиты reader'а: n_tensors ≤ 4096,
   n_kv ≤ 4096, длина строки ≤ 1 МиБ, суммарные размеры — checked.

## Интерфейсы фазы (фиксированы, использовать дословно)

```rust
// ── crates/ggrs-gguf (новый крейт, zero deps, НЕ зависит от ggrs-core) ──────
pub enum GgufValue {
    U8(u8), I8(i8), U16(u16), I16(i16), U32(u32), I32(i32), F32(f32),
    U64(u64), I64(i64), F64(f64), Bool(bool), Str(String),
    ArrStr(Vec<String>), ArrI32(Vec<i32>), ArrF32(Vec<f32>), ArrU32(Vec<u32>),
} // достаточный поднабор; чужие типы массивов reader скипает с Err "Фаза 5"

#[derive(Clone, Copy, PartialEq)] pub enum GgmlDType { F32 } // = 0 в файле; остальные — Ф5
pub struct TensorInfo { pub name: String, pub ne: Vec<u64>, pub dtype: u32, pub offset: u64 }

pub struct GgufWriter { /* kv: Vec<(String, GgufValue)>, tensors: Vec<(TensorInfo, Vec<u8>)> */ }
impl GgufWriter {
    pub fn new() -> Self;
    pub fn add_kv(&mut self, key: &str, v: GgufValue);              // порядок сохраняется
    pub fn add_tensor(&mut self, name: &str, ne: &[u64], data: &[u8]); // F32; len == prod(ne)*4
    pub fn write(self, path: &std::path::Path) -> std::io::Result<()>;
    // layout: magic "GGUF" u32 LE, version=3 u32, n_tensors u64, n_kv u64;
    // KV: name(u64 len + utf8) + type u32 + значение (string = u64 len + utf8;
    //     array = elem_type u32 + n u64 + элементы);
    // tensor info: name + n_dims u32 + ne[u64;n] + dtype u32 + offset u64
    //     (offset — от начала data-секции, каждый тензор выровнен на 32);
    // pad нулями до кратности 32 → data-секция.
}

pub struct GgufFile { pub kv: Vec<(String, GgufValue)>, pub tensors: Vec<TensorInfo>, /* data */ }
impl GgufFile {
    pub fn read(path: &std::path::Path) -> std::io::Result<GgufFile>; // hardening AUDIT-2
    pub fn get(&self, key: &str) -> Option<&GgufValue>;
    pub fn tensor_f32(&self, i: usize) -> std::io::Result<&[f32]>;   // проверка dtype+границ
}

// ── crates/ggrs-model/src/gguf_map.rs (T5/T7) ───────────────────────────────
pub fn bytes_to_unicode() -> [char; 256];       // каноническая таблица GPT-2 (в брифе — дословно)
pub fn export_gguf(ckpt: &std::path::Path, bpe: &Bpe, cfg: &GptConfig,
    out: &std::path::Path, duplicate_output: bool) -> std::io::Result<()>;
/// Обратный путь: наши собственные GGUF (llama-арка, F32, gpt2-токенизатор).
/// Возвращает конфиг (из метаданных), BPE (из tokens+merges) и заполняет веса построенного Gpt.
pub fn import_gguf(path: &std::path::Path, ctx: &mut Context)
    -> std::io::Result<(GptConfig, Gpt, Bpe)>;
```

### T1 (pro): AUDIT-3 — паника worker'а не должна вешать compute

**Files:** `crates/ggrs-core/src/compute.rs`, тест `crates/ggrs-core/tests/threading_panic.rs`.

- [ ] Poison-механизм: каждый worker исполняет узел внутри `std::panic::catch_unwind`
  (AssertUnwindSafe); при панике взводит общий `AtomicBool` и ШТАТНО доходит до барьера
  (источник зависания — пропущенный `wait`). После каждого барьера все потоки проверяют
  флаг и чисто выходят; главный поток по завершении scope re-panic с сообщением
  «compute: worker паниковал на узле <op>» (op сохранить в AtomicUsize по номеру узла).
- [ ] Дешёвая статическая валидация до запуска потоков (id/ne/nb/dtype узлов графа
  в границах арены) — данные-зависимые ошибки (индексы get_rows) ловит poison-путь.
- [ ] Тесты: (а) get_rows с заведомо невалидным индексом в данных → compute паникует на
  ГЛАВНОМ потоке (`#[should_panic]`), а не висит — обернуть в поток с таймаутом 30с,
  чтобы регресс проявлялся как провал, а не вечный CI; (б) существующие 1==4-потока
  тесты не тронуты и зелёные; (в) счётчик паник: ровно одно сообщение при 4 потоках.
- [ ] Commit: `fix(core): AUDIT-3 — poison-флаг в compute, паника worker'а не вешает граф [pro]`.

## Риски и стоп-краны

1. **llama.cpp отвергает tied-модель без `output.weight`** → готовый флаг
   `--duplicate-output` (T5/T6), +30 МБ к файлу d10m — приемлемо.
2. **Претокенизатор `gpt-2` неизвестен конкретной сборке llama.cpp** (ключ
   `tokenizer.ggml.pre` валидируется по списку) → зафиксировать версию llama.cpp в
   отчёте; при отказе попробовать `"default"` — решение на T8, не менять T5 вслепую.
3. **Расхождение rope** (NORM против NEOX): симптом — связный round-trip у нас (T7
   зелёный), но мусор в llama.cpp. Диагностика по чек-листу T8; фикс — метаданные
   (`llama.rope.dimension_count`, scaling type), НЕ трогая ядра.
4. **Byte↔unicode тонкости** (пробел/перенос/не-ASCII) — закрыты golden-тестами T5 и
