# Инженерные заметки из полных текстов (вторая ступень конвейера)

Провенанс: агент DeepSeek + CORE API (полные тексты) с добором через arXiv.
Метки: 📄 — из полного текста (CORE); 🔎 — из arXiv abs/HTML (абстракт+метаданные).

## 📄 BitNet b1.58 ([2402.17764](https://arxiv.org/abs/2402.17764)) — прочитан целиком (23 663 симв.)

**Absmean-квантование весов** (формулы 1–3 статьи):
```
γ = (1/(n·m)) · Σ|W_ij|                       # среднее |W| по матрице
W̃ = RoundClip(W/(γ+ε), −1, 1)                # тернар {−1, 0, +1}
RoundClip(x,a,b) = max(a, min(b, round(x)))
```
- Активации: 8 бит, absmax per-token к [−Q_b, Q_b], без zero-point.
- В высокой точности остаются: embedding и LM head (явно в тексте).
- Архитектура LLaMA-стиля: RMSNorm, SwiGLU, RoPE, без bias — **совпадает с ggrs**.
- Обучение с нуля, RedPajama 100B токенов; LR-схема в тексте НЕ приведена.
- Бенчмарк-сет для сравнения: PPL WikiText2/C4 + ARC-e/c, HellaSwag, Winogrande, PIQA, OBQA, BoolQ.

## 🔎 QuEST ([2502.05003](https://arxiv.org/abs/2502.05003), группа Алистарха)

- STE заменён **trust-оценкой градиента**: явная минимизация ошибки между шумным
  градиентом по квантованным состояниям и истинным полноточным градиентом.
- Квантование через **нормализацию Адамара + MSE-оптимальную подгонку**; стабильно
  вплоть до 1 бита весов И активаций; оптимум качества/размера — 4 бита.
- **Есть открытый код: [github.com/IST-DASLab/QuEST](https://github.com/IST-DASLab/QuEST)** —
  референс для нашей Фазы 7 (сверять градиенты, как сверяем forward с numpy).

## 🔎 Continual QAT ([2502.11895](https://arxiv.org/abs/2502.11895))

- Стратегия «16-бит → 1.58-бит» **предпочтительнее** обучения в 1.58 с нуля.
- Два конкретных приёма при переключении: **сохранить состояние оптимизатора** и
  **вводить силу квантования постепенно** — меньше loss spikes.
- Точные доли бюджета — в PDF (абстракт не раскрывает); добрать при реализации Фазы 7.

## 🔎 Sub-100M QAT, 1345 прогонов ([2605.25966](https://arxiv.org/abs/2605.25966)) — НАШ масштаб

- **Warmdown 33%** от бюджета обучения — оптимум независимо от битности (FP16/INT8/INT6)
  и размера (15M–100M).
- **Практическое правило: настроить LR-расписание один раз на FP16 и применять без
  изменений к INT8/INT6 QAT** — прямо экономит нам сетку экспериментов спидрана.
- INT4: ниже 50M выбор расписания тонет в шуме сидов; от 50M — уверенно warmdown 33%.
- Лог-линейная модель потерь INT6 предсказала 5/5 held-out размеров — масштабирование
  на нашем диапазоне предсказуемо.

## Что это меняет в плане ggrs

1. **Фаза 3 (спидран)**: LR-расписание = cosine/linear c warmdown 33% как дефолт;
   найденные на FP32/FP16 гиперпараметры переносимы на будущие INT8/INT6 прогоны.
2. **Фаза 7**: старт не с нуля в квантах, а «тёплый переход» по Continual QAT
   (сохранение состояния оптимизатора + плавный ввод квантования) — совместимо с
   нашим error-feedback крючком из Фазы 2.
3. **Фаза 7, тернарный трек**: absmean-квантование BitNet — 5 строк, реализуем как
   один из квант-типов; embedding/LM head держим в высокой точности.
4. **Верификация Фазы 7**: код QuEST (IST-DASLab) — внешний эталон для gradcheck
   квантованного backward.

## Ограничения конвейера (зафиксировано)

- CORE не индексирует свежие arXiv-препринты (2502.*, 2605.* отсутствовали) —
  фолбэк: arXiv HTML напрямую.
- CORE требует User-Agent (Cloudflare режет python-urllib → 403).
- Агент без явного запрета реконструирует «алгоритмы» по абстрактам — в промпте
  обязательна формула «только факты из фактически прочитанного текста».
