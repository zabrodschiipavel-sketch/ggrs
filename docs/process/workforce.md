# Организация труда ggrs: архитектор, контролёр и исполнители

Роль Claude (Fable Max) — **главный архитектор и главный инженер**: декомпозиция фаз,
брифы с точными интерфейсами, задачный файл для контролёра, приёмка выполненной работы
(построчное ревью дифов, собственный прогон тестов), критические фиксы. Роль
**Sonnet 5 — контролёр исполнения**: по задачному файлу (`.superpowers/sdd/phase3-tasks.md`)
диспатчит исполнителей, проверяет их отчёты прогоном, итерирует при провалах, делает
рабочие коммиты с меткой исполнителя. Рутинный код пишут исполнители. Правило эскалации:
две проваленных попытки исполнителя → уровень выше; три → задача возвращается
архитектору как ошибка брифа. Цикл: архитектор (брифы) → контролёр (исполнение) →
архитектор (приёмка).

## Маршрутизация задач

1. Полный код в брифе, 1–2 файла → **deepseek-chat**.
2. Требуется вывести/спроектировать (математика, новые ядра) → **deepseek-v4-pro**.
3. Многофайловая интеграция, git-операции, харнесс-специфика → **Haiku** (чёткий бриф) или **Sonnet 5** (нужно суждение).
4. Провал → эскалация на ступень; вторая ступень провалила → бриф виноват, чинит архитектор.
5. Всё проходит ревью архитектора: диф читается глазами, тесты перепроверяются,
   clippy `-D warnings`, критика письменно (что не так и почему), исполнитель переделывает.

## Инфраструктура

- `dev_agent.py` (scratchpad): DeepSeek-исполнитель с песочницей — `read_file`/`write_file`/`list_dir`
  строго внутри репо (без `.git`), `run_cargo` с белым списком (test/build/clippy/fmt).
- **cargo-раннер** (`.superpowers/runner/cargo_runner.sh`, запускает архитектор своим шеллом):
  Windows Application Control блокирует rustc в процессной цепочке python → cargo
  исполняется внешним bash-циклом через файловый протокол request.json/response.json.
  Перед сессией dev_agent раннер должен быть жив.
- Системные промпты исполнителей: рядом, в `docs/process/prompts/`.
- Ключи API: `~/.ggrs-secrets.json` — вне репозитория.

## Дисциплина промптов для исполнителей (выжимка уроков)

- «У тебя НЕТ инструментов кроме перечисленных» — без этого minimax/qwen галлюцинируют tool-вызовы.
- «Только факты из фактически прочитанного» — иначе реконструкции по абстрактам.
- «Перед правкой — прочитай файл; после правки — тесты; финал — отчёт без tool-вызовов».
- Тесты исполнителей проверять на то, что они действительно исполняют граф/код
  (урок Task 9 второго круга: тест без вызова compute сравнивал нули).
- Точные сигнатуры Interfaces в каждом брифе — исполнитель не видит соседних задач.
