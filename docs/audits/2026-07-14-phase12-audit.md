## 2. Новизна — честная оценка

**Фазы 1–2 сами по себе научной новизны не содержат** — это порт архитектуры
ggml плюс учебниковый reverse-mode autograd и AdamW. Заявлять обратное было бы
самообманом и репутационным риском.

**Инженерная редкость** (по нашему исследованию, docs/research/): единственный
Rust-движок обучения ggml-архитектуры. Ближайшие соседи: llm.rs-порты —
захардкоженный backward одной модели без общего autograd; candle/burn —
GPU-first, не ggml/GGUF; llama.cpp finetune — без претрейна и обучаемых
embeddings; у llm.c нет gradcheck-дисциплины.

**Заделы под новизну, уже встроенные в фундамент**: ECO-крючок в AdamW::step
(ставка №2, arXiv 2601.22101); type traits под блочные кванты; телеметрия
per-op (спидран); warmdown-33 из свежайшей литературы (2605.25966);
тотальный gradcheck.

**Вердикт**: в руках — добротный и редкий, но не новаторский фундамент.
Новаторство запланировано (CPU-спидран, ECO-в-GGUF, self-evolution) и
фундамент под него подготовлен осознанно.

## 3. Качество кода

Сильные стороны: zero deps; unsafe локализован (47 точек: ядра+арена) с едиными
конвенциями и обоснованием у каждого `unsafe impl`; плотные guard-assert'ы
(dtype+плотность в каждом ядре); стиль единообразен; телеметрия и
детерминизм (бит-в-бит по потокам) встроены; леджер и метки исполнителей в
истории коммитов.

Слабости (не блокируют, зафиксированы): `scale` копирует строку перед
умножением (фьюз — Фаза 6); rustdoc на публичном API фрагментарен (докрутить
перед анонсом); нет бенчмарк-крейта (Фаза 6); ядра loss/get_rows_back
однопоточные (по профилю ≤5% времени — приемлемо).

## 4. Упущения двух фаз (найдено аудитом, вход Фазы 3)

1. **Нет сохранения/загрузки весов** — спидран без чекпоинтов невозможен;
   решаем в Фазе 3 (простейший формат или ранний GGUF-writer из Фазы 4).
2. **Инициализация**: есть только равномерный Lcg [−0.5,0.5); GPT требует
   масштабированный normal (≈0.02) — добавить Box-Muller в util (Фаза 3).
3. **Память**: арена без переиспользования; для 10M модели на ctx≥256
   forward+backward-граф может потребовать сотни МБ — оценить в начале
   Фазы 3, при необходимости поднять приоритет планировщика памяти.
4. `build_backward` нельзя вызывать дважды на одном ctx (дублирует узлы) —
   задокументировать в rustdoc.
5. Rope только NORM-режим (NEOX — к Фазе 5, для чужих моделей).
